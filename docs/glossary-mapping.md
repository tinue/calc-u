# Glossary mapping

How the names of Calc-U-59 (`v2.3.0`) and Calc-U-1600 (`v0.8.1`) map to
the terms in [`GLOSSARY.md`](GLOSSARY.md). Briefing §1.5 requires every
rename of a visible label, menu item or help text to be listed here; those
are the rows of "Visible renames". Code renames are listed so documents can
refer to them. The renames landed during migration (phase 6, M-n steps and
the parts' simplifications); each row says "done (M-n)" with the old names
after "was", "kept" where a code name stays, or "open" where the user has
not ruled yet.

Sources: the naming-conflicts table in
[`inventory/divergence-matrix.md`](inventory/divergence-matrix.md), the
product inventories, and the products' code at the pins.

## Naming code before the renames (history)

Until migration renamed the code, every document, skill, memory file and
comment used the glossary term and added the code name of the time after
it, for example "app session (code: `TIAppPart`)". The renames landed in
phase 6, and the parentheses went with them. The rule still applies to the
names that are kept or open below (for example "memory module (code:
`SoftwareDefinedCard`)" while the card classes of Calc-U-1600 are open).

|---|---|---|
