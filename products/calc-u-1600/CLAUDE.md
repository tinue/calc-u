# Calc-U-1600

Calc-U-1600 lives in `products/calc-u-1600/` of the source repository tinue/calc-u (ADR 0002). Work happens on short branches merged into `main` (ADR 0029); a release is tagged `calc-u-1600-vX.Y.Z` (ADR 0028). The repository's `CLAUDE.md` holds the current phase and its rules; they come first.

Before removing, simplifying or "fixing" code in a review or cleanup, read `docs/background/Decisions.md`. It lists deliberate choices that look wrong at first sight. When a recurring review question gets settled, add it there.

## Test builds

All C++ builds go through the repository's root CMake project (ADR 0003; options `CALCU_PRODUCT_59`, `CALCU_PRODUCT_1600`, `CALCU_FRONTEND_QT`, `CALCU_TESTS`), the Emscripten ones too (`build/web`); this directory does not configure on its own. Run the test suite optimized: `tools/run_tests.sh` (`-O1`, the repository's `build/tests` tree) or the `CoreTests` target of any root tree (`-O1` in Debug). When chasing a bug — a debugger, stepping, inspecting variables — first build a full-debug tree and work there, leaving the other trees as they are:

```sh
cmake -S ../.. -B ../../build/debug -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCALCU_FRONTEND_QT=OFF -DCALCU_TESTS_DEBUG=ON
cmake --build ../../build/debug --target CoreTests
```

A test file registers its tests with `TEST(name)` of the repository's one runner, `library/testing/TestHarness.hpp` (ADR 0038; `CHECK`, `CHECK_EQ`, `SKIP_UNLESS` for a missing ROM); there is no list of tests to keep. `tools/run_tests.sh <substring>` runs the tests whose name contains it. Every CTest entry is in a test group (ADR 0031; `docs/test-groups.md` at the repository root): a tree has the Frequent group (`CoreTests`, `calcu_preset_check.CalcU1600Presets`, `calcu_preset_check.CalcU1600Templates`; ≤ 60 s), and with `-DCALCU_TESTS_LONGER=ON` / `-DCALCU_TESTS_CHECKPOINT=ON` also the Longer and Checkpoint ones (`ctest -L longer`).

## Harness

`calcu` is the family's harness (LIB-11, `features/LIB-11-harness/` at the repository root): the product without a window, on the library's app session, in emulated time only, so two runs give the same replies. Build the target `calcu` of a root tree (`cmake --build ../../build/tests --target calcu`; the program is `build/tests/library/harness/cli/calcu`). It finds the ROMs in `roms/` through the product's lookup (`sharp::lookUpRoms`), the module definitions in `frontends/qt6/resources/cards/` (and the ROM set's CE-502B), the bundled presets in `examples/` (`examples/bundle.yaml`), and starts the startup model (the PC-1500A under the default settings) cold booted, at key readiness (LIB-18; its machines are `app/SharpProductMachines`).

- One-shot: `calcu --product 1600 wait 2s then lcd then ticks` (commands parted by `then`; exit status 0, 1 at the first refusal, 2 when it cannot start).
- `calcu --product 1600 serve`: one command per line on standard input, one reply per line (`done`, `done <n>` and n lines, `refused: <reason>`); `--json` gives one object `{"done","result","reason"}` per reply. From Python: `library/harness/python/calcu_serve.py`.
- First commands: `wait <2s|500ms>`, `key-down`/`key-up <key ID>`, `lcd` (rows of text, `indicators:`, `not text:`; no cursor cell yet), `display`, `state <topic>`, `capabilities`, `ticks`, `audio <file.wav>`, `quit` (`calcu --help`).
- Machine control (LIB-18): `model <PC-1500|PC-1500A|PC-1600>`, `variant <A01|A03|A04|New|Old>`, `attach <place> <peripheral>[:<variant>]` (`attach printer CE-1600P:old`), `detach <place>`, `reset`, `cold-boot`, `power-cycle`; each replies when the machine is ready for keys again. No settings or save folder of yours is touched unless `--settings`, `--save-folder`, `--output-folder` name them.
- Typing (LIB-5): `key <name> ...` (key IDs and `break` for `on`, any case; replies when the last key is up) and `type <text>` (the text and ENTER; replies when ENTER is up). Neither waits until the machine is idle: `wait` does.
- Debugger (LIB-10): `targets`, `registers`, `pause`, `step`, `step-over`, `step-out`, `resume`, `break`, `watch`, `peek`/`poke` (spaces `me0`, `me1`, `me1-written` of the LH5801/LH5803, `memory`, `io`, `io-written` of the SC7852; `bank=`, `vbank=`), `history`, `disassemble`, `trace <file>|off` (into `--output-folder`), `symbols`, `pause-on-start cpu`.
- Paper (LIB-8): `paper marks|png <path>|copy|cut [CE-150|CE-1600P]`, `cut-paper`.
- Program files (C1600-2): `pc1600 file-kind <file>` (what it is; a WAV's files), `pc1600 load-basic <file> [<n>]`, `pc1600 type-basic <file>` (typed through the ROM's editor; program mode first), `pc1600 load-code <file> [<n>] [address=<a>] [length=<l>] [cpu=<lh5803|z80>] [run]` (the reply: range, area, bank, NEW, the starting command, warnings). Refusals are `refused: <file>: <reason>`.
- Presets (LIB-6, C1600-4): `preset <file>|examples:<path>` (format 2 only; version 1 is refused with the hint), `check-preset <file>…`, `preset-list`, `wait` without a duration (until idle), `expect`/`not-expect` (text in one line of `lcd`, or `/regex/`), `screenshot <name>` (Copy Screen's picture, into `--output-folder`), and the steps as commands. The product's keys and sections are in `app/SharpPresetKeys` (`program:`, `host-drive:`, `slot-N-rom:`, `bus-rom:`, `debug:`), its rules in `app/SharpPresetRules`.
- Media (LIB-7): `media` (the topic: the modules, disks and tapes, templates and saved instances, what each place holds), `media import <file>`, `media export <kind> <name> <path>`, `media delete <kind> <name>`; the steps as commands: `floppy { name: Formatted, side: 1 }`, `tape { file: x.tape.yaml }`, `eject floppy|tape`, `saveas { place: slot-1, as: live, name: Mine }`. Kinds `battery-backed-module` (`.card.yaml`), `floppy-disk` (`.floppy.yaml`, version 2, sides 0 and 1), `cassette` (`.tape.yaml` with its WAV, in the tape folder); the codecs in `app/SharpMediaKinds`, the places in `core/Machine/SharpMediaPlaces`. The run's save folder is empty unless `--save-folder` names one.
- Not yet: the other `pc1600 …` commands, memory dumps (later features). Until M-51, `pc1500_cli`, `pc1600_cli` and the probes stay the tools for memory dumps and the INSPECTOR views; they load presets through the library's loader (`tools/CliPresetRun.hpp`).

## Core, Shared, frontends

Three layers (docs/developer/Shared-Architecture.md): `core/` is the hardware, `app/` all app logic that isn't drawing, `frontends/qt6/app/` the desktop GUI, `frontends/web/` the WebAssembly browser GUI.

- Non-GUI logic goes in `app/` (or `core/`), never in `frontends/qt6/app/`; Qt classes translate types and show what Shared decides.
- Above `core/`, the machine is only a `calcu::machine::Machine` (C1600-1): built with `calcu::machine::build(sharp::sharpCatalogue(), SharpMachineBuilder, request)`; Sharp-only functions are capabilities (`c1600.*` kinds, `core/Machine/SharpProductKinds.hpp`); what has no seam yet goes through `core/Machine/LegacyCalls.hpp` (adapters, each with the step that removes it). Every ROM image comes from the one ROM lookup at the start (`sharp::lookUpRoms`, `core/Machine/SharpRoms.hpp`, LIB-12) and its `calcu::roms::RomSet`; nothing else reads a ROM file (the CTest `CalcU1600NoOwnRomLookup`; the one exception is the host-drive ROM, `sharp::readHostDriveRom`). Descriptors, kinds and adapters live in `core/Machine/`. Never include or name `PC1500Machine`/`PC1600Machine` in `app/`, `frontends/`, `tools/` or `dev/`: the CTest `CalcU1600MachineIncludeCheck` (`tools/check_machine_includes.sh`, Frequent and CI) fails.
- Core and Shared: portable C++20, standard library only, single-threaded, never blocking; the machines hold no lock (ADR 0009). Long machine work is a resumable job (`core/Job.hpp`: `co_await job::run(machine, n)`, the library's `calcu::sessions::Task`); coroutine parameters by value.
- Every frontend hosts the library's app session (`library/sessions/`, LIB-3) with the product's part `app/SharpAppPart` (the library's parts it brings: typing, peripherals, presets, startup, the loaders, paper, debugger, media (LIB-7's `MediaPart`: the topic `media`, `media.choose`, `media.turn`, `media.name-and-save`, `media.start-new`, autosave; `app/SharpMediaKinds`); the product commands `c1600.mount-host-drive`, `c1600.ce1600p-rom`, `app/SharpTopics.hpp`) and talks to it by messages: the start, the model and variant switches, attach, detach, Reset and Cold boot are LIB-18's commands (`start`, `model`, `variant`, `attach`, `detach`, `reset`, `cold-boot`), a preset is LIB-6's `load-preset {ref}`; pacing is the library's (LIB-17, `app/PacingProfiles`). The product writes no session class of its own (CTest `CalcU1600NoOwnSession`), and an operation never runs to its end on a frontend's thread: it runs in parts, one per host call. `app/SharpSession` (`makeSharpSession`) builds the session for a native host, which talks to it through the library's `calcu::sessions::Listener` (Qt6 `MachineController`, the tests' `app/tests/SessionFixture.hpp`, `tools/wasm_smoke`); the Web engine builds the session in `frontends/web/bindings.cpp` for the library's worker, with `app/SharpWebPart` for what the page draws. Keys and typing go through the library's typing engine (LIB-5; the profiles and keyboard maps in `app/SharpTyping`, the frontends send `host-key-down`, `screen-key-down`, `paste`, ...); the debugger is the library's `DebuggerPart` (LIB-10; `app/SharpDebuggerSetup`, the targets in `core/Debug/SharpDebugging`) and the paper the library's `PaperPart` (LIB-8; `app/SharpPrinters`, `core/Connector/PlotterPaperOutput.hpp`); the DAP's layer is in `app/dap/`, its server in the Qt frontend until M-50.
- A change to `core/` or `app/` passes `tools/run_tests.sh` and `tools/build_wasm_check.sh`, and the Qt app builds; a change the web client sees also passes `frontends/web/build.sh` + `frontends/web/run-tests.sh`.
